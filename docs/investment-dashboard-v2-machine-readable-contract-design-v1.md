## 2. 为什么选择 JSON Schema

当前项目没有引入 Zod 等额外校验库，因此本阶段不修改运行依赖。

先使用标准 JSON Schema 的好处：

1. 不改变现有项目环境；
2. 能被 TypeScript、Node、Python 等多种实现读取；
3. 后续可以自动生成类型或校验器；
4. Research Bridge、数据库导入、备份程序可以共享同一规则；
5. 未来即使底层数据库变化，合同仍可保持稳定。

## 3. 行业研究合同

### 3.1 行业总档案

每个行业必须存在一个 `IndustryResearchProfile`。

它固定包含 14 个研究槽位 M0-M13：

0. 研究边界与投资假设
1. 行业认知
2. 宏观政策与产业地位
3. 需求侧分析
4. 供给侧分析
5. 生产 / 技术路径与关键瓶颈
6. 生命周期与周期位置
7. 产业链结构与利润池
8. 竞争格局与护城河
9. 商业经济模型、财务与关键指标
10. 投资表达与标的映射
11. 估值、预期差与投资结论
12. 催化剂、风险与证伪条件
13. 持续跟踪计划

每个槽位可以是：

- 深度研究；
- 标准研究；
- 轻量研究；
- 不适用；
- 尚未研究。

前端以后只重点展示有内容的模块，空模块默认收起。

### 3.2 行业专属扩展

14 模块是统一骨架，但行业仍可有自己的专属内容。

例如：

- 焦煤：安监、进口煤、库存、焦化开工、铁水；
- 创新药：靶点、临床分期、监管、BD、峰值销售；
- 商业航天：发射、复飞、单位入轨成本、星座、付费用户。

这些使用 `IndustryExtension` 保存，不需要再为某个行业写特殊页面分支。

## 4. ChatGPT 一键推送合同

### 4.1 研究贡献包

ChatGPT 完成一次研究后生成 `ContributionBundle`。

它可以同时包含：

- 总结；
- 观点方向；
- 宏观驱动；
- 行业驱动；
- 14 模块中的部分更新；
- 证据；
- 催化剂；
- 风险；
- 证伪条件；
- ETF / 股票等投资表达；
- 后续研究任务；
- 原聊天 Markdown 引用。

### 4.2 推送预览

Research Bridge 收到后先生成 `ContributionPlan`。

用户看到的是中文业务预览，例如：

- 更新焦煤 M4 供给侧；
- 更新 M6 周期位置；
- 新增 3 条证据；
- 将行业观点从中性调整为看多；
- 新建 1 个库存跟踪任务。

这一阶段不修改正式状态。

### 4.3 一次确认正式提交

用户点击一次“确认推送”后，用 `ContributionCommitRequest` 提交。

必须同时检查：

- 预览内容没有被替换；
- 当前数据没有被其他操作修改；
- 重复提交不会重复写入；
- 所有模块要么一起成功，要么整体失败。

用户不需要在看板中再次点击“发布”。

## 5. 原聊天全文

用户已经确认保留研究对话全文。

每次正式推送时，可以生成一份 Markdown 文件，同时生成 `ConversationArchiveManifest`，记录：

- 这份对话属于哪一次贡献；
- 文件保存位置；
- 文件校验值；
- 时间。

Markdown 的作用是以后复核和恢复上下文，不直接作为行情、宏观数据或资产计算的数据源。

## 6. 名称识别与防重复

新增独立 `Entity Registry & Resolution` 合同。

它解决的问题包括：

- “焦煤”和“炼焦煤”是否同一行业；
- “黄金ETF华安”和“518880”是否同一资产；
- 同一公司 A 股 / H 股身份如何区分；
- Theme 和 Industry 是否被混淆。

原则：

- 每个正式对象有稳定 ID；
- 名称和简称只是 alias；
- 高置信匹配才自动关联；
- 不确定时必须让用户确认；
- AI 不能因为没找到就自动创建一个新的正式行业或资产。

## 7. 资产账本合同

### 7.1 Account

未来支持：

- 证券账户；
- 基金账户；
- 银行账户；
- 现金；
- 实物资产；
- 保险；
- 虚拟货币；
- 其他。

V1 实际只导入当前长期价值账户。

### 7.2 Asset

每项资产支持：

- 主分类；
- 策略桶；
- 多标签；
- 用户自定义顺序；
- 用户自定义覆盖。

因此以后可以灵活形成“纯黄金 / 红利 / 全球科技 / 行业网格 / 现金”等个人视角分类。

### 7.3 Transaction 与 CashFlow

交易和资金流必须分开。

交易记录“买卖了什么”；资金流记录“钱从哪里来、去了哪里”。

外部新增、工资、内部转账、分红、费用等不能混为一类。

尤其内部账户转账不能重复计算为新增本金。

### 7.4 Position Snapshot

保留每个重要日期的持仓快照，用于：

- 与交易流水核对；
- 修正漏记；
- 计算资产配置；
- 年度复盘。

## 8. 定投合同

分成两部分：

- `DcaPlan`：计划与规则；
- `DcaExecution`：每周实际执行结果。

每日限购、最小交易单位等限制按照“有生效日期的规则”记录，而不是覆盖旧规则。

因此以后 006373 限购变化不会改写历史。

每周都能保留：

- 计划金额；
- 实际金额；
- 待补金额；
- 是否延期；
- 延期原因；
- 对应真实交易。

---

## 9. 历史资产迁移

使用 `LegacyAssetImport`。

正式基准：2026-08-14。

迁移流程：

旧 Excel / 策略文件
→ 解析候选数据
→ 统计将导入多少账户、资产、交易、资金流、持仓和定投记录
→ 显示异常
→ 用户确认
→ 正式写入。

更早历史不强行反推。

## 11. 备份和恢复合同

### 11.1 BackupManifest

每次备份记录：

- 备份时间；
- 数据库版本；
- 包含哪些文件；
- 文件大小；
- SHA-256 校验；
- 加密方式；
- 已上传到哪些网盘；
- 每个远端副本是否验证成功。

### 11.2 RestorePlan

恢复前必须先：

- 校验文件完整；
- 验证能解密；
- 验证数据库版本兼容；
- 在临时区成功打开；
- 再备份一份当前数据库。

任一关键检查失败，不允许覆盖当前数据库。

## 12. 权限合同

ChatGPT 的默认角色为 `AI_RESEARCHER`。

简单理解：

### 可以直接做

- 读取研究；
- 读取用户授权的资产信息；
- 生成研究推送预览；
- 生成资产导入预览；
- 查看备份状态；
- 准备恢复预览。

### 必须用户确认

- 正式推送研究；
- 写入已经发生的交易记录；
- 写入资金流；
- 提交定投执行；
- 正式恢复数据库；
- 手工立即执行一次备份。

### 永远不给 AI

- 真实买卖下单；
- 读取券商密码；
- 读取备份加密密钥；
- 任意 SQL；
- 任意删数据库；
- 修改管理员权限；
- 删除审计历史。

研究权限和资产权限彼此独立，不能因为能读行业研究就自动获得工资、交易和现金流数据。
